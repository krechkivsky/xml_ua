# Як плагін використовує XSD

Плагін використовує одну локальну схему `templates/UAXML.xsd`; шлях до неї задається в `common.py` (`xsd_path`). Окремої схеми для старих XML немає.

Під час відкриття XML віджет дерева читає XSD у `tree_view.py`: будує перелік дочірніх елементів, їх порядок, типи, обов’язковість і підказки. `xsd:documentation` показується як підказка, а текст `xsd:appinfo` — як підпис елемента дерева. Структурні елементи та варіанти `choice` використовуються для додавання нових вузлів.

Перевірка валідності виконується `lxml.etree.XMLSchema` для активного XML-дерева. Відкриття XML не зводиться до цієї перевірки: помилки валідації показуються у віджеті, а редактор зберігає можливість працювати з деревом. XSD також використовується для впорядкування дочірніх елементів.

Статус конструкції зберігається як атрибут `ua:status` в `xsd:appinfo` (`urn:xml-ua:schema-status`), щоб не змінювати текст підпису для дерева. Схема та алгоритм плагіна залишаються універсальними.
